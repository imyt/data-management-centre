# ADR 0002: Backend layout and the contract pipeline

- Status: accepted; decisions 1 to 3 superseded by [ADR 0003](0003-single-backend-app-with-modules.md); the `VITE_API_BASE_URL` part of decision 6 is replaced by [ADR 0004](0004-environments-database-and-frontend-backend-pairing.md) once that is accepted
- Date: 2026-10-18

## Context

The first vertical slice (the owner inbox, architecture §15) needs a backend, and `contracts/openapi.json` as the only link between backend and frontend. The docs disagreed on the layout:

- **Architecture §14 / D7:** a repo-root uv workspace with `apps/api`, `apps/worker`, `apps/web`, `libs/`, and one `packages/dmc_<context>` per bounded context from day one, with boundaries enforced by import-linter, so contexts can be split out before production.
- **`.github/copilot-instructions.md` and `backend.instructions.md`:** top-level `backend/ frontend/ contracts/ infra/`, with one `backend/app/` organised by layer (`api/v1`, `services`, `repositories`, `models`, `schemas`) and explicitly not split by context.

The frontend had already been merged in `frontend/` (ADR 0001), not `apps/web`.

## Decisions

1. **Hybrid layout.** Keep the top-level folders from the copilot instructions (`backend/`, `frontend/`, `contracts/`, later `infra/`). Inside `backend/`, use the architecture's uv workspace:
   ```
   backend/
     pyproject.toml          # workspace root: dev tools, ruff, pytest, import-linter
     apps/api/               # dmc_api: settings, error mapping, router wiring only
     packages/dmc_common/    # base: errors, pagination, ErrorResponse, Page
     packages/dmc_platform/  # health (later auth, audit, outbox)
     scripts/export_openapi.py
   contracts/openapi.json    # committed, generated
   frontend/src/api/         # committed, generated by hey-api
   ```
   Context packages (`dmc_registry`, `dmc_operations`, …) are added when a slice needs them, not ahead of time.
2. **Three tiers inside each package.** Each package keeps the §14.2 anatomy, and backend.instructions.md's tier rules apply inside it: `api/` (router, HTTP only) → `application/` (services: business rules, permissions, transactions) → `infrastructure/` (repositories and SQLAlchemy models). Plus `domain/` (entities), `schemas.py` (Pydantic read/write models) and `public.py` (the only module other packages may import).
3. **Boundaries are enforced by import-linter**, configured in `backend/pyproject.toml`. Today the only contract is `layers: dmc_api > dmc_platform > dmc_common`. Each new context adds its layer and a `forbidden` internals contract (§14.4).
4. **Errors.** Services raise `dmc_common` domain errors (`NotFoundError`, `InvalidInputError`, `ConflictError`, `PermissionDeniedError`). `dmc_api` maps them to 404/400/409/403. Every error, including 422 validation and unknown routes, uses one `ErrorResponse` shape (`code`, `message`, `details`, `request_id`). `X-Request-ID` is echoed, or generated if missing.
5. **Explicit operation IDs are mandatory.** The app's `generate_unique_id_function` raises, so a route without an `operation_id` fails the spec export and the tests.
6. **Contract pipeline.** `npm run api:sync` in `frontend/` runs `backend/scripts/export_openapi.py` (via `uv`) and then `openapi-ts` (`frontend/openapi-ts.config.ts`, plugins: client-fetch, typescript, sdk). A backend test fails when `contracts/openapi.json` is out of date with the app. The client's `baseUrl` comes from `VITE_API_BASE_URL` through `src/lib/api-config.ts` (`runtimeConfigPath`).
7. **hey-api runs on TypeScript 6.** The app uses TypeScript 7, which no longer ships the JS compiler API that hey-api 0.99 calls. `frontend/.pnpmfile.cjs` gives `@hey-api/openapi-ts` its own `typescript@~6.0.2`. (A pnpm override does not apply to peer dependencies.) Delete the hook once hey-api supports TypeScript 7.
8. **Package manager.** The frontend uses pnpm (lockfile, `pnpm-workspace.yaml`), and `npm run <script>` still works for running scripts.

## Consequences

- Architecture §14.1's `apps/web` and `libs/` are not used. The frontend stays in `frontend/`, and the generated client lives in `frontend/src/api/`, not `libs/api-client`.
- `backend.instructions.md` is updated to describe the package layout. Its tier rules still hold, scoped to each package.
- The `examples` resource in `dmc_platform` is scaffolding: a reference for the tier pattern, cursor pagination and the error shape. Delete it (with its tests) once the first real resource exists.

## Not done yet

- Database: SQLAlchemy, Alembic, Postgres roles per schema, and `infra/` Docker Compose. These come with the first slice that persists data.
- Auth, audit, structured (JSON) logging, and the worker app.
- Playwright e2e in CI. The screenshot baselines are win32-only (ADR 0001), so the Linux CI jobs skip e2e. The CI jobs themselves (`.github/workflows/backend.yml` and `frontend.yml`, path-filtered, which also check that `contracts/` and `frontend/src/api/` are up to date) are done.
- The hey-api TanStack Query plugin. Add it in `openapi-ts.config.ts` when the first feature uses the client.
- Starlette warns that `TestClient` over `httpx` is deprecated in favour of `httpx2`. Switching is a dependency change, so it is left for later.
